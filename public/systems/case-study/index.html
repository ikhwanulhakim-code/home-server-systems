Context and constraints

A useful system built from ordinary limits.

The machine has limited resources, sits behind a home connection without a public IP, and must stay manageable during short power interruptions.

The design favors simple tools, private administration, repeatable application delivery, and recovery steps that a single operator can understand.

Architecture

Two paths with different trust boundaries.

Administration remains private. Selected web applications will use a separate public route.

Engineering decisions

Each tool answers a specific constraint.

Access / Verified

Tailscale administration

Remote management stays on a private network rather than exposing SSH to the public internet.

Check: access works from both home and external networks.
Authentication / Verified

Ed25519 key-only SSH

Password login is removed from the remote authentication path after the trusted key is verified.

Check: login succeeds without password fallback.
Boundary / Verified

UFW allowlist

Administrative traffic is accepted only through the home network and Tailscale interface.

Check: both approved routes recover after reboot.
Addressing / Verified

Router-managed reservation

The router provides a stable local address while keeping network allocation in one place.

Check: the same address returns after a complete reboot.
Runtime / Verified

Docker Compose

Application definitions stay repeatable, reviewable, and separate from the host operating system.

Check: lifecycle, logs, and restart behavior are verified.
Routing / Verified

Host Nginx

One entry point selects applications by hostname while container ports remain bound locally.

Check: separate hostnames reach separate containers.
Public web / Planned

Cloudflare Tunnel

Selected sites can be published without router port forwarding or a public IP.

Check: pending public HTTPS verification.
Power / Verified

Battery guard

The laptop battery covers short interruptions and preserves a safe shutdown margin.

Check: a timer evaluates discharging state and threshold.

Lessons

What this project demonstrates.

  • Security controls are safer when replacement access is tested first.
  • Simple architecture is valuable when one person must operate and recover it.
  • A deployment is more credible when its verification and limitations are visible.
